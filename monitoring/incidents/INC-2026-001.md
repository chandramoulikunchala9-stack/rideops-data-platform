## Impact
`ingest_payments` failed on all three attempts on 2026-10-19. Its dependants (`silver_transform`,
`data_quality_checks`, `gold_aggregations`, `export_to_postgres`) were **CANCELLED**, so dashboards
showed 2026-10-18 data for about 27 hours. No data was lost: the files stayed in the landing zone.

## Timeline (UTC)
| Time | Event |
|---|---|
| 00:04 | Scheduled run fails: `DELTA_FAILED_TO_MERGE_FIELDS ... DOUBLE and STRING` |
| 00:11, 00:19 | Automatic retries fail with the same error (not transient, so retrying cannot help) |
| 00:20 | `failed_pipeline` alert, on-call acknowledges |
| 02:40 | Root cause confirmed by inspecting one landing file: `"amount": "216.19"` (quoted) |
| 2026-10-20 03:10 | Payments team fixes the export; next run backfills 2 days (records_read doubled) |

## Root cause
The payment provider's new exporter serialised `amount` as a JSON **string**. Delta schema
enforcement rejected the write, because merging DOUBLE with STRING is not a safe schema evolution.

## Resolution
1. Confirmed with the source team; they redeployed the exporter with numeric amounts.
2. Re-ran the pipeline; the incremental checkpoint picked up both days' files.
3. Verified `daily_city_summary` totals for 10-19 and 10-20 against the payments source counts.
